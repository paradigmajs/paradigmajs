## 🚀 Selected work

A selection of the **types of products and technical challenges I work with**. Commercial source code is not always public. Click a category to explore.

<details>
<summary><b>📍 Location-aware & interactive mobile apps</b> · React Native · Maps · GPS</summary>
<br/>

**Engineering focus:** geolocation, route and movement tracking, dynamic maps, reactive UI, background behavior, device limitations and API communication.

**Typical challenges:** battery usage, geolocation accuracy, offline transitions, app permissions and cross-platform consistency.

**Approach:** separate location services, business rules and presentation; test on physical devices; treat imperfect sensor data as an expected scenario.
</details>

<details>
<summary><b>📦 Commerce & logistics platforms</b> · React · Node.js · MongoDB</summary>
<br/>

**Engineering focus:** product catalogs, order flows, multi-role interfaces, delivery status, third-party marketplace integrations and operational dashboards.

**Typical challenges:** data normalization, upstream API differences, pricing rules, delayed status updates and clear customer communication.

**Approach:** explicit state transitions, isolated provider adapters, validated data contracts and clear separation of user-facing and internal workflows.
</details>

<details>
<summary><b>🏢 CRM & operational software</b> · System design · APIs · RBAC</summary>
<br/>

**Engineering focus:** custom CRM platforms, admin panels, role-based permissions, data models, reporting and workflow automation.

**Typical challenges:** complex authorization, changing business rules, auditability and maintainability.

**Approach:** understand the actual operational process before designing endpoints or tables.
</details>

<details>
<summary><b>⚡ Real-time & automated systems</b> · WebSocket · Events · Integrations</summary>
<br/>

**Engineering focus:** live status updates, interactive experiences, real-time dashboards, external services and automated business processes.

**Typical challenges:** reconnection, event ordering, idempotency, error handling and synchronization.

**Approach:** establish the event contract first, keep the server authoritative and handle retries deliberately.
</details>

## 🏗️ How I build

<details open>
<summary><b>01 / Understand the business problem</b></summary>
<br/>
Clarify user roles, data flows, edge cases, constraints, and what success should look like. The best technical decisions are usually made before the first component.
</details>

<details>
<summary><b>02 / Design the architecture</b></summary>
<br/>
Define module responsibilities, data models, integration boundaries, authentication and API contracts. Prefer simplicity that can evolve over complexity that merely looks impressive.
</details>

<details>
<summary><b>03 / Implement and validate</b></summary>
<br/>
Build feature by feature, validate real workflows, handle loading and error states, and keep business rules testable and separate from UI rendering.
</details>

<details>
<summary><b>04 / Release, observe and improve</b></summary>
<br/>
Handle deployment configuration, integration testing, production behavior, user feedback and iteration. A feature is not finished just because it compiles.
</details>
